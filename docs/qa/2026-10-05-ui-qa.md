# UI QA pass, 2026-10-05

Hands-on pass of the local dev build (`main` at 670791e) in Chrome, driven as a fresh account (`qa@example.test`, Dev role) from login through onboarding, a full workout, food logging, Progress, Settings, a Bulgarian pass and the admin unlock. Chrome won't make a window narrower than 500 px, so most of the pass ran at a 500 px viewport (the CSS has no width breakpoints, so it lays out like a phone). The 390 and 320 px checks used CSS `zoom` on the real page; framing the app in an iframe is blocked by its headers, which is correct. Animations were checked by slowing the View Transition durations tenfold in the live page and screenshotting mid-flight.

The recordings and screenshots taken during the pass (six GIFs, from login through the Bulgarian pass) were not kept in the repository; file names mentioned below refer to them.

## Corrections (added 2026-10-06, while fixing)

- **H6:** the claim that the Undo failures coincided with View Transition aborts is wrong. The aborts were logged at 13:06, 13:10 and 14:46 UTC; the failed Undos were at 13:16–13:17. The first failure was most likely the 6 s toast expiring during tool latency. Undo was hardened anyway (10c9849), and browser tests tap it at 0.5, 2, 4 and 5.5 s.
- **Setup "Goal / Goal"** was a screen-reader-only label under the section title, not a visible duplicate (it was still redundant and is gone). Only the Settings "Goal" label was a visible duplicate.
- **"Plates you have" twice** is a correct pair: a screen-reader `legend` and an `aria-hidden` label. Nothing to fix.
- **M5:** placeholders already used `--label-3`; the problem was typed values in `--label-2`, close enough to read as placeholders.
- **M6** didn't reproduce in Chromium or WebKit at 390 px. The scroll margins were added as the standard guard, and a browser test covers it.
- **Decimals:** the Bulgarian table suggested decimal commas. The decision was dot decimals everywhere, so the commas went the other way.

## Summary

The app is in good shape visually. Navigation is fast, the pager-style tab slide and push/pop transitions are smooth, and there were no console errors or failed requests during normal use. The real problems are a handful of **silent data-loss and mis-tap traps in the workout screen**, where the app is used one-handed between sets. Most of the rest is small and quick to fix: inconsistent labelling, scroll position lost after every server round-trip, and a short list of Bulgarian phrasing problems.

The five worth fixing first:

1. Editing a logged set and moving on looks saved but isn't (H1).
2. The Undo toast and the rest timer share a slot, so a late Undo tap hits Skip (H2).
3. Added warm-up and extra-set rows vanish on any re-render (H3).
4. Sets aren't pre-filled from the previous set when there's no suggestion (H4).
5. Unsaved template card edits are dropped without warning (H5).

Severity: **H** = data loss or a likely mis-tap during normal use; **M** = clearly wrong or annoying, with a workaround; **L** = polish.

## High

**H1. Edits to a logged set are silently discarded.** In an active session, tapping a logged set's weight makes it editable. I changed 60 to 62.5 and tapped elsewhere. The row showed 62.5, but after a reload it was 60 again. The edit only saves if you tap the check button again (its label quietly becomes "Save changes"), and nothing marks the row as changed. *Fix:* save on `change`/blur, or at least show a dirty state on the row and swap the check for a distinct save icon. `Views/Shared/_SetRow.cshtml:8-15`.

**H2. The Undo toast and the rest timer occupy the same spot; Undo is under Skip.** After deleting a set during rest, the toast replaces the timer at the bottom. Undo (x≈445) and the timer's Skip (x≈460) are almost on top of each other. When the 6 s toast expires, the timer slides back under your finger. My late Undo tap hit **Skip**: the rest was cancelled and the set stayed deleted. *Fix:* stack the toast above the timer instead of replacing it, or keep the toast until the user scrolls or taps elsewhere. `wwwroot/js/motion.js:479-487`, `.toast` and `.rest-timer` in `app.css`.

**H3. Added warm-up and extra-set rows are client-only until checked.** Add set and Warm-up insert rows that aren't saved. Any server re-render (Move up, Swap, a reload, iOS evicting the page while locked) removes them: five rows before reload, three after. SPEC 8 says the active session must be fully restorable. *Fix:* persist the slot count server-side when a row is added, or keep added rows in the `localStorage` queue the way pending sets are kept.

**H4. No carry-over between sets when there's no suggestion.** On a first-ever exercise, set 2 and set 3 are blank after set 1 is logged at 60 × 10, so every set means typing the weight again. *Fix:* when there's no target, use the previous logged set in this exercise as the placeholder or suggestion for the next row. `_SetRow.cshtml:28-29` already supports `data-suggested`.

**H5. Template card edits are lost without warning.** Each exercise card in the template editor has its own "Save changes". Changing Working sets to 4 and tapping back to Templates silently discards it. *Fix:* autosave on change (htmx `hx-trigger="change"`), or one Save for the page with a `beforeunload`/soft-nav guard.

**H6. Undo for food entries failed in 2 of 4 real attempts.** Deleting an entry from its page and tapping Undo in the toast sent no request in two tries; the entry stayed soft-deleted (`DeletedAt` set). With fetch and submit instrumented, a later attempt worked, and so did Undo for template exercises. I couldn't pin the cause. The two failures coincided with View Transition aborts that the app logged at the same moments (see M14). Worth a targeted look at what happens to `#toast` when a transition is aborted mid-swap.

## Medium

**M1. Dark-mode segmented controls inside cards show the selected segment darker than the rest.** The thumb is `--surface-2` (#2c2c2e), but the track is `--fill` over a #1c1c1e card, which comes out around #323236. "Male", "Dark" and "English" all look unselected (`setup-segment-and-gray-values.png`). On the black page background (Progress) it reads correctly. iOS uses #636366 for the dark thumb. `app.css:226`.

**M2. The compact top-bar title overlaps the back label.** With a long template name, scrolling the template editor gives "‹ Templates" running into "Upper A — heavy pressing and rowin…" (`topbar-title-overlap.png`). The title is capped at `max-width: 60vw` but is centred without regard for the back label's width. On the workout summary the back label is the full template name and fills the whole bar (`summary-back-label.png`). *Fix:* cap `.topbar-back` at around 35% and ellipsize it, and size the title as `min(60vw, 100% - 2 × back width)`.

**M3. Scroll position resets to the top after every server action.** Removing an exercise at the bottom of a template, swapping the 5th exercise in a session, "Copy yesterday's lunch" and Quick add all bring you back to the top. You lose your place, and after Quick add you can't see the entry you just added. *Fix:* keep `scrollY` across same-URL soft navigations in `nav.js`, or scroll to the affected element (`.exercise` already has `scroll-margin-top: 60px`).

**M4. Taps during a page transition are swallowed.** A tap in the roughly 340 ms after a tab switch (the View Transition overlay) is dropped. Tapping Train and then quickly tapping Templates did nothing. Fast one-handed use hits this. *Fix:* skip the transition when the user taps again, or call `transition.skipTransition()` on `pointerdown`.

**M5. Filled values look like placeholders.** Input values use `--label-2` (#98989d), the same colour as placeholders. In setup, "0 % of weight", "Auto g per kg" and "Estimate kcal" look like entered values, and real values look empty. iOS uses grey for values in read-only rows only. *Fix:* use `--label` for typed values and `--label-3` for placeholders.

**M6. Validation scrolls the field under the sticky header.** Pressing Save on an empty setup form scrolls the Sex control behind the "Set up" bar, so the browser's bubble points at nothing. Only `.exercise` has a `scroll-margin-top`. *Fix:* `:where(input, select, .segmented) { scroll-margin-top: 64px }`.

**M7. Food search isn't live and ranks basic foods badly.** Exercise search filters as you type, but food search only runs on Enter. For "banana" it ranks *Pepper, banana, raw*, *banana chips* and *Melon, banana* first, and "Bananas, raw" isn't in the top 20. Ranking is `word_similarity` and then name length, so the plural USDA name loses to any name containing the exact word (`Features/Food/FoodItemService.cs:35-43`). There are also three "Bananas, raw" rows in FoodItems. The section header says "Saved foods" for USDA rows. *Fix:* add a prefix/stem bonus (`Name ILIKE q || '%'`, or match `q || 's'`), debounce-search on input, dedupe, and rename the header.

**M8. The fallback parser's matches look trustworthy when they aren't.** With no AI key, "a banana" matched *Mousse strawberry banana apple carrot* and "cooked rice" matched *Wild rice*, both with the green "Database" badge. The Check foods screen has no "choose a different food". The only options are editing per-100 g numbers or starting over. *Fix:* add a "Change food" link that opens search pre-filled with the item text. Mark low-score matches differently from confident ones.

**M9. Changing an entry's amount leaves the old grams in its name.** "150 g cooked rice" changed to 200 g shows as "150 g cooked rice · 200 g · 202 kcal" on Food and in Recent (`food-entry-grams-mismatch.png`). *Fix:* strip a leading quantity from the description when saving the parse, or show the matched food's name.

**M10. "Move up" on the first exercise, "Move down" on the last (session only).** The template editor hides these correctly; the session menu doesn't. Tapping "Move up" on the first exercise re-rendered the page, which also deleted my unsaved warm-up row (H3).

**M11. Set numbering showed 1, 2, 4 after a swipe-delete.** The DOM had three counter increments, but the third row rendered "4" until the next swap. It's a stale CSS counter after the htmx `outerHTML swap:180ms` in Chrome (`set-numbering-1-2-4.png`, `app.css:524-527`). I haven't confirmed it on iOS Safari. Rendering the number server-side avoids it.

**M12. Native `confirm()` for destructive actions.** Finish workout, archive template, delete workout, delete saved meal, remove passkey and log out everywhere use `window.confirm` (`site.js:69`). In an installed iOS web app that shows a system alert headed with the domain, unlike the app's own sheets and menus. Finish also doesn't mention that 3 planned sets were never logged. *Fix:* a small confirm sheet using the existing sheet component, with "3 sets not logged" when relevant.

**M13. Charts show legend entries that draw nothing.** On Progress, Target, Maintenance and Aim each have a single data point (today) with `pointRadius: 0`, so no line appears even though the legend lists them. Minimum is drawn across all 28 days, including days before the profile existed. *Fix:* for series with fewer than 2 points, draw a point, or extend the step line to the chart edge (`wwwroot/js/progress.js:143-165`).

**M14. View Transition aborts are logged as app errors.** `ErrorEvents` got "Transition was aborted because of invalid state. Document hidden" and "…Viewport size changed" with no stack. On a phone this will fire whenever the screen locks mid-navigation, which adds noise to the feedback digest and Telegram. *Fix:* ignore `AbortError`/`InvalidStateError` from transitions in `feedback.js:424`.

**M15. No way to create a custom exercise.** SPEC 7 lists "Custom exercises" in Settings. There's no UI for it anywhere: not in Settings, and the picker's "No exercise matches." has no create link (`ExercisesController` only has settings routes).

**M16. Settings mixes save models.** Theme and language apply instantly. Everything from Profile through Bar & plates (four sections) shares one "Save profile" button at the very bottom, with nothing to show there are unsaved changes. Time zone and Weight jump sit under "Goal".

## Low

- After a wrong password, focus lands on `<main>` instead of the password field.
- Setup has a "Goal" section heading with a "Goal" label directly under it. The same duplicate appears in Settings, as does "Plates you have" twice.
- Setup doesn't preselect anything, not even Maintain.
- The Admin unlock button says "Unlock with Face ID" on an account with no passkey, with no hint to add one.

**Today, Food and Progress**
- Today repeats the trend weight in three places: "Trend weight 82.5kg" (no space), "Logged today: 82.5 kg, trend 82.5 kg", and Progress "82.5 kg / Trend now: 82.5 kg".
- The Today protein ring says "130 g to your protein minimum" while the line below says "0 of 180 g protein (minimum 130 g)". That's two numbers to reconcile at a glance.
- Food totals use five label patterns: "protein of 180 g" with "min 130 g", "carbs" over a range, "fat" over a range, "fiber of 35 g", "saturated fat, up to 28 g". The data-gap notes say "At least:" under fiber and "Incomplete:" under saturated fat for the same condition. With no data the value renders as "— g".
- "Nothing was logged for lunch the day before." is shown with a green success check. It should be neutral. "Copy yesterday's …" is offered even when yesterday is empty.
- Food lets you page to future dates and log there. Past and future days drop all targets from the totals card. "Yesterday" shows no date while Today does.
- The quick-add sheet title doesn't name the meal. Protein, carbs and fat aren't marked "Optional", though the spec says they are, while fiber and sat fat are.
- An unticked item on Check foods keeps full contrast. It should dim.
- The food entry page doesn't show which database food was matched, and the macros have no units ("6 protein").
- Swipe-to-delete works on sets but not on food entries, which must be opened to delete.
- On the barcode screen an invalid code clears the typed digits. The hint says "8 to 14 digits" but the spec lists EAN-8/13 and UPC-A/E.
- Progress's weekly sets says "week 41". A date range would be clearer.

**Workout**

- The summary's back link goes to the session editor (the same place as "Edit workout"), not Train.
- The summary says "0 New records" for a first session that Progress then shows as an 80 kg e1RM.

**Templates and navigation**
- The template editor offers reorder only one step per menu open.
- The exercise picker doesn't mark exercises already in the template, and a duplicate is added silently.

- The Undo toast follows you to other tabs (removed on Templates, still offered on Train).
- Train's empty state shows an "Edit" link with nothing to edit. "Create a template" appears in three places.

**Visual and locale**
- Theme switching crossfades the whole page for 340 ms, and the midpoint is a muddy grey with ghosted double text.
- On pop (back), the new large title appears in place at once while its page is still sliding in from the left.

## iPhone checklist after the fixes

What no browser engine in the tests covers. Run it on both iPhones, from the installed app (Add to Home Screen), after the `qa-fixes` deploy. Each line is a pass or a fail; note the phone and iOS version for any fail.

- [ ] Start a workout, log a set: the screen stays on through a full rest (wake lock).
- [ ] Let a rest timer run out with the phone unlocked and the sound on: it beeps once.
- [ ] Lock the phone mid-rest for a minute, unlock: the timer shows the right time left, and the page is as you left it.

## My suggestions

These go beyond fixing what's broken:

- **Treat the workout screen as the one that must never lose input.** H1, H3 and H4 share a cause: state that lives only in the DOM. If every keystroke in a set row went into the existing `localStorage` queue (as a draft, not a pending set), reloads, re-renders and phone locks would all become safe. The machinery is already there.
- **Keep the user's place after every action.** One `nav.js` change (restore `scrollY` on same-URL swaps, or scroll to the changed element) fixes M3 everywhere.
- **"Last time" line per exercise.** Even with progression suggestions, showing the previous session's sets ("Last: 60×10, 60×9, 60×8") under the exercise name is the single most useful thing in a gym log. It also covers H4 on first repeats.
- **Food matching:** a "Change food" link on each Check foods row, plus prefix-boosted search, would make the no-AI fallback usable and cut how often the AI matcher is needed.
- **Plates sheet:** draw the plates as sized, colour-coded bars (the IPF colours for 25/20/15/10). It reads faster than chips with numbers.
- **Today after a workout:** show "Done today: Upper A, 4 min, 3 sets" instead of offering the same template as "Up next".
